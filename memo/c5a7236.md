TCP化に一旦成功し、とりあえずネットワーク越しにベンチが回せるようになった。
しかし、ベンチマーク側でエラーが出た。

## 失敗原因

### 1. ポート枯渇（"resource temporarily unavailable"）

`request()` が呼ばれるたびに毎回 `net.Dial` で新しいTCP接続を張っていた。
Load フェーズで `Set` を10万回呼ぶ = 10万回接続を張ろうとする。

`defer conn.Close()` 自体は正しく動いているが、TCPの仕様として接続を閉じた後も
OSはそのポートを **TIME_WAIT 状態**として約60秒間保持する。
その間は同じポートを再利用できないため、空きポートが枯渇する。

```text
接続1: Close() → ポートがTIME_WAITで60秒塞がる
接続2: Close() → 別のポートがTIME_WAITで60秒塞がる
...
接続N: もう空きポートがない → "resource temporarily unavailable"
```

### 2. nil ポインタパニック

`net.Dial` が失敗したとき `conn` は `nil` になる。
しかし `slog.Error` でログを出した後も処理が続き、`defer conn.Close()` で
`nil` のメソッドを呼んでパニックした。

```go
conn, err := net.Dial("tcp", "localhost:8080")
if err != nil {
    slog.Error(...)  // returnしていないので処理が続く
}
defer conn.Close()  // conn が nil → パニック
```

### 根本原因

1操作ごとに接続を作って捨てている設計。接続は使い回す必要がある。
